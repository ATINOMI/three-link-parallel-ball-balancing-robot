# CAN1 编码器角度 PID / 目标电流控制

## 当前行为

- PA0 低电平按下，TIM6 每 1 ms 扫描，连续 20 次确认状态变化。
- 控制 M3508 + C620，电调 ID 为 **1、2、3**，各自独立角度 PID，直接输出目标电流给 C620，CAN1 为 **1 Mbps**。
- PD0 是 CAN1_RX，PD1 是 CAN1_TX；电机接板上 CAN1_H/CAN1_L。
- 各电机首次有效反馈分别建立输出轴相对零点。每次有效按下，所有在线电机的目标同时增加 **10°**。
- 长按不重复触发；松开也需稳定 20 ms，之后才能再次触发。
- 未收到反馈或离线时的按键事件不累积。
- 支持多圈累计：350° → 360° → 370°，不会在 360° 时反向寻找零点。
- 上电不自动执行角度步进，但在线后会保持初始位置。

“10°”按减速箱输出轴计算，默认杆直接连接输出轴。如果杆与输出轴之间还有齿轮、皮带或连杆机构，需按实际传动关系进一步换算。

## 角度方向

三个电机统一反转：`MOTOR_DIRECTION = -1`。Qt/PS5 的 +10° 对应之前 -10° 的实际转动方向；-10° 对应之前 +10° 的方向，PA0 也使用新的正方向。

目标与界面反馈角度使用同一正方向。累计编码器计数乘方向系数后参与 PID，PID 的输出也乘同一系数再发给电调，以保持负反馈。只翻转电流或只翻转编码器会破坏闭环方向。

遥测的 `rpm`、`cmd`、`fb` 和 `ecd` 保留电调原始协议方向；例如静止时增加目标 +10° 对应 cmd 为负值，实际角度向 +10° 增加。

## 数据和控制链

`PA0 / Qt / PS5 指令 → 输出轴目标角度 → 角度 PID → CAN1 目标电流 → C620 内部电流闭环 → 电机`

STM32 每 1 ms 用编码器累计角度计算目标电流，不再经过转子目标转速和速度 PI。CAN 返回的 rpm 用于显示；反馈电流用于观察电调状态，不另做一个 STM32 电流 PID。C620 的电流闭环负责跟踪 CAN 下发的电流目标。

角度误差 `e = target - angle`，电流指令 `cmd = MOTOR_DIRECTION * clamp(Kp*e + I - Kd*(angle - previous_angle)/dt, -3000, 3000)`。积分每次增加 `Ki*e*dt`、限幅 ±1000；输出饱和且误差会加重饱和时暂停积分。微分对反馈求导，目标直接增加 10° 不会触发微分冲击。每个电机有独立的 PID 状态。

发送标准数据帧 `0x200`、DLC=8，DATA[0:1]、DATA[2:3]、DATA[4:5] 分别为电调 1、2、3 的有符号电流指令，高字节在前；DATA[6:7] 为 0。三路指令在同一帧发送，控制周期为 1 ms。

三个精确接收过滤器分别接收标准数据帧 `0x201`、`0x202`、`0x203`，验证 DLC=8。反馈的 0~8191 是转子编码器位置，不是输出轴角度。相邻编码器差值修正跨圈后累计：

`输出轴角度 = MOTOR_DIRECTION × 累计转子编码器计数 × 360 / (8192 × 减速比)`

默认减速比为 `3591/187`。跨圈算法要求相邻有效反馈之间的转子位移小于半圈，不能恢复断线期间丢失的圈数。

## D 项启用条件

每个电机独立记住最近一次非零目标步进方向。目标增加时关闭 D，只计算 P/I；目标减少时使用 `MOTOR_ANGLE_KD`，并在之后没有新指令的控制周期中保持启用。新的增加指令（包括 PA0）会关闭 D。上电、反馈超时及恢复重建目标时默认关闭 D。

判断依据是逻辑目标角度增加/减少，与反转后的 CAN 电流正负、当前角度是否为负、瞬时位置误差的正负无关。同一周期合并后的步数为零时，不改变 D 开关。切换时保留积分，PID 始终记录上一周期反馈，避免重新启用 D 时使用过时角度。

## 调试参数

在 `Core/Application/Inc/motor_control.h` 中修改：

| 参数 | 当前值 | 含义 |
|---|---:|---|
| MOTOR_CONTROL_COUNT | 3 | 当前控制电调 1~3；过滤器及帧范围按三电机实现 |
| MOTOR_GEAR_RATIO | 3591/187 | 转子转数 / 输出轴转数 |
| MOTOR_DIRECTION | -1 | 编码器角度与电流输出的方向映射，支持 +1 / -1 |
| MOTOR_KEY_STEP_DEG | 10 | 每次有效按下增加的输出轴角度 |
| MOTOR_CONTROL_PERIOD_S | 0.001 | TIM6 控制周期，单位秒 |
| MOTOR_ANGLE_KP | 100 | 比例增益，raw / 度 |
| MOTOR_ANGLE_KI | 10 | 积分增益，raw / (度·秒) |
| MOTOR_ANGLE_KD | 5 | 反馈微分增益，raw·秒 / 度 |
| MOTOR_MAX_INTEGRAL_CURRENT | 1000 | 积分项电流限幅，raw |
| MOTOR_MAX_CURRENT | 3000 | 电流指令绝对值限幅，单位为协议原始值，并非安培 |
| MOTOR_FEEDBACK_TIMEOUT_MS | 100 | 反馈超时阈值 |

PID 数值以 `can_motor.h` 为准，需结合实际杆负载调参。即使按键只按一次，仍每毫秒根据剩余误差持续计算电流。

C620 指令 ±16384 raw 对应 ±20 A，因此 ±3000 raw 约为 ±3.66 A，±1000 raw 约为 ±1.22 A。这是指令换算，实际电流观察 Qt 的 fb 字段。协议来源：[C620 官方用户手册](https://cdn-hz.robomaster.com/robomasters/public/document/RoboMaster%20C620%20Brushless%20DC%20Motor%20Speed%20Controller%20V1.0.pdf)。

调参时先用 `Ki=0` 调 Kp 与 Kd：响应慢且 cmd 未限幅可适当增加 Kp；超调或来回摆动先减小 Kp 或适当增加 Kd。再逐步增加 Ki 消除静止后的持续偏差。若 cmd 持续为 ±3000 而实际角度不动，需检查电机/电调、负载和电流上限，重复发送步进只会继续增大目标。若 cmd 高频正负跳动，降低 Kd 并检查编码器反馈更新。

这里不再设置目标转速限幅；实际转速由负载、PID 与电流上限共同决定。

调试数组下标 `[0]`、`[1]`、`[2]` 分别对应电调 1、2、3。调试器可观察：`motor_online`、`motor_target_angle_deg`、`motor_actual_angle_deg`、`motor_current_command`、`motor_tx_errors`。

每个电机独立检测反馈超时，超时电机发送零电流并重置其控制器，其他在线电机继续闭环；Bus-Off 时三路均发送零电流；超时恢复后重新建立相对零点，不继续旧目标。CAN 断线时 MCU 无法保证零电流帧送达电调。若只是 Bus-Off 而反馈没有超时，恢复时以当前累计角度重新设定保持目标。

## 工程集成

- `Core/Application/Src/motor_control.c`：电调协议解析、反馈累计、离线处理和角度 PID 到目标电流控制。
- `Core/Algorithm/`：复用原工程 PID 实现。
- `main.c`：GPIO/TIM6/CAN1 初始化后启动 CAN，清除 TIM6 初始更新标志再启动定时器。
- CAN1_RX0 和 TIM6 中断均为优先级 1，避免反馈更新与控制计算互相抢占。
- `Key.ioc` 与源码同步配置 CAN1、PD0/PD1 和 PA0 普通上拉输入。
- 用户源码加入顶层 CMake；HAL CAN 驱动加入 CubeMX 驱动列表，重新生成时不会重复链接。

## 验证范围

通过 ARM GCC 的 Debug 编译和链接。桌面模拟 HAL 测试运行实际电机控制、PID 和提取的按键函数，验证角度 PID 直接输出正负电流、限幅/抗积分饱和/反馈微分阻尼、三电机同帧字节打包、独立反馈/控制、单路超时不影响其他电机、反馈过滤、抖动计数清零、长按不重复、松开后再按增加 10°、多圈换算、反馈超时和恢复、Bus-Off 停止输出。

未连接电机、未烧录。首次实机验证需确认三个电调反馈 ID 分别为 0x201、0x202、0x203、波特率一致和输出轴传动关系；观察目标角度是否从 0、10、20°递增，再根据实际响应调节 PID。

三个目标同时增加 10°不代表三个轴的瞬时轨迹完全同步；三路独立闭环，实际到达时间取决于各自负载。离线电机忽略当次按键，恢复后重新建立目标。


## USB CDC 数据回传

主循环每 100 ms 回传三行，M1/M2/M3 分别对应电调 1/2/3。在串口助手中打开 C 板的 COM 口（当前 COM6），文本/ASCII 显示即可，波特率可选 115200、8N1；此固件使用 USB CDC，不依赖串口助手选择的 UART 波特率。

示例（仅说明格式，不是实测数据）：

```text
t=1200 M1 online=1 target=10.00 angle=9.85 rpm=12 cmd=35 fb=28 temp=32 ecd=4321
```

字段：t=上电毫秒，online=反馈在线状态，target/angle=目标/当前输出轴相对角度（度），rpm=转子转速，cmd=发送电流原始指令，fb=电调反馈电流原始值，temp=温度（摄氏度），ecd=0~8191 原始转子编码器。离线时反馈字段保留最近一次数据，应以 online=0 判断数据已失效。

`Core/Application/Src/motor_telemetry.c` 负责取一致快照、格式化和非阻塞发送。USB 未枚举或发送忙时跳过；静态发送缓冲区在上一帧传输完成前不会被改写。`Core/Application/Src/motor_command.c` 在 USB 接收回调中解析 `STEP 1 +10` / `STEP 2 -10` 等命令并入队，由 TIM6 应用到指定在线电机；Qt 和 PS5 只修改选中电机，PA0 仍同时增加三个在线电机的目标。

## 分层结构

```text
Core/
  BSP/Inc, Src/          bsp_can、bsp_micro_usb：板级通信
  Algorithm/Inc, Src/    pid：独立 PID 算法
  Application/Inc, Src/  motor_control、motor_command、motor_telemetry
  Inc, Src/             CubeMX 初始化、中断入口和 main
```

- BSP CAN 负责精确过滤器、FIFO 接收分发、标准帧发送、Bus-Off 查询和发送取消，不依赖电机或 PID。
- BSP Micro USB 封装 CDC 就绪检查、非阻塞发送及接收/复位回调。发送数据复制到 BSP 静态缓冲区，传输完成前不改写。
- Application 负责电调协议、编码器累计、三个轴的控制状态、步进命令解析及遥测格式化。
- PID 只依赖 C 标准头文件，不依赖 HAL 或 main.h。
- USB_DEVICE 和 Middlewares 保留 CubeMX 生成位置；usbd_cdc_if 的 USER CODE 段仅调用 BSP，BSP 通过已注册回调通知应用。
- main 在启动 USB 之前调用 Motor_Init 注册回调，再启动 1 ms 控制定时器。
- CubeMX 的 GPIO/CAN/TIM/USB 外设初始化与 MSP、中断入口保留原位，顶层 CMake 管理新增用户模块。

本次重构保持参数、正反方向 D 项切换、按键行为、USB STEP 协议和遥测格式。
